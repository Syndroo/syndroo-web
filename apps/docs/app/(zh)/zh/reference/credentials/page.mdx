    <h1 id="credentials">凭证</h1>
    <p className="lede">在本地工作流中，凭证只读取一次，按提供商的模式验证，然后由 Core 保存。之后发布时绝不会重新读取你导入的环境变量或文件。可选的自托管 Server 会在独立的私有状态中保存部署机密。</p>

    <h2 id="sources">两个明确的来源</h2>
    <ul>
    <li><code>{"--from-env"}</code> 只读取 <code>{"SYNDROO_CREDENTIALS"}</code>：一个 JSON 对象，最大 64 KiB。</li>
    <li><code>{"--credential-file"}</code> 读取一个结构相同的私有 JSON 文件。</li>
    </ul>
    <p>同时传入两者，或提供商需要凭证却两者都不传，都会被拒绝。在终端交互运行时，还会提供字段逐项输入；提供商标记为机密的字段会关闭回显读取。非交互运行从不猜测，也从不阻塞。</p>

    <h2 id="server">服务器凭证</h2>
    <p><strong>自托管 Server。</strong>Server 设置使用 <code>{"@syndroo/cli@0.7.0"}</code> 和 <code>{"@syndroo/cloudflare@0.7.0"}</code>。Server 流程不使用上文所述的本地 <code>{"SYNDROO_CREDENTIALS"}</code> 导入。</p>
    <p><code>{"server connect threads"}</code> 通过隐藏的终端输入、<code>{"THREADS_APP_SECRET"}</code> 或 <code>{"--app-secret-stdin"}</code> 读取 App Secret。Cloudflare 认证来自现有的 Wrangler 登录。限定范围的 CI bearer 保存在私有位置，或在设置请求恢复时通过 <code>{"--ci-token-stdin"}</code> 提供。</p>
    <p>绝不要把 App Secret、CI bearer、Cloudflare admin bearer、<code>{"SECRET_KEY"}</code> 或 <code>{"RUNTIME_KEY"}</code> 放入命令参数、日志、聊天消息或仓库文件。部署凭证可以通过受保护的输入，与 <code>{"server deploy --yes --credentials-stdin"}</code> 一起导入。参见<a href="/zh/getting-started/server/">部署服务器</a>和<a href="/zh/reference/cli/#server">Server 命令参考</a>。</p>

    <h2 id="after">凭证保存之后</h2>
    <p>Core 将凭证保存在本地凭证存储中，并在连接上记录引用；插件只收到其自身操作所需的内容。发布不依赖环境变量或导入文件继续存在，因此连接成功后即可删除该文件。</p>
    <p>连接断开时，保存的凭证会被释放。断开只会删除本地记录：Syndroo 绝不会撤销平台凭证，因此还应到平台撤销。每份<a href="/zh/platforms/">平台指南</a>都说明其撤销流程中已有文档记录的部分。</p>

    <h2 id="browser">本地浏览器授权</h2>
    <p>LinkedIn、Threads 和 Mastodon 都通过浏览器完成的授权动作建立连接。本地 CLI 会自行完成这三者的 OAuth 回调。使用 <code>{"--redirect-uri"}</code> 时，它会在进程内准确绑定该回环主机、端口和路径，并且只接收一次重定向；默认值是预先可注册的回环 URI，绑定需要控制终端，没有控制终端时会报告待处理动作并以退出码 0 结束。使用 <code>{"--callback-url -"}</code> 时，它会改为从标准输入读取重定向 URL。包含 <code>{"code"}</code> 或 <code>{"state"}</code> 的回调 URL 会在命令行上以 <code>{"CALLBACK_URL_INVALID"}</code> 拒绝，因为机密不得进入参数向量。这条本地回调路径只通过针对本地 HTTP 服务器的模拟测试验证；尚未连接真实的 LinkedIn、Threads 或 Mastodon 账号。</p>
