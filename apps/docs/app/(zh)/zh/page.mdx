    <h2 id="install">1. 构建候选版本</h2>
    <p>需要 macOS 或 Linux 上的 Node.js 24.19 或更新版本。候选版本不在软件包注册表中，因此要从产品仓库构建，再从工作区打包：</p>
    <pre data-label="terminal"><code>{"git clone https://github.com/Syndroo/syndroo\ncd syndroo\nnpm ci\nnpm run build\nnpm pack --workspace @syndroo/cli --pack-destination ./artifacts\nnpm install --global ./artifacts/syndroo-cli-0.7.0-rc.1.tgz"}</code></pre>
    <p><a href="/zh/getting-started/local-cli/">本地 CLI</a> 会完整介绍配置文件、状态根目录和首次运行。</p>

    <h2 id="connect">2. 连接一个账号</h2>
    <p><code>{"syndroo connect"}</code> 每次只读取一个凭证来源：使用 <code>{"--from-env"}</code> 时读取环境变量 <code>{"SYNDROO_CREDENTIALS"}</code>，使用 <code>{"--credential-file"}</code> 时读取一个私有 JSON 文件。它从不读取 <code>{".env"}</code> 文件，也不会猜测凭证。</p>
    <pre data-label="terminal"><code>{"export SYNDROO_CREDENTIALS='{\"identifier\":\"you.bsky.social\",\"password\":\"APP_PASSWORD_PLACEHOLDER\"}'\nsyndroo connect bluesky --from-env --label work"}</code></pre>
    <p>五个提供商的准确字段名见{" "} <a href="/zh/reference/credentials/">凭证</a>；每份{" "} <a href="/zh/platforms/">平台指南</a>都会说明凭证的来源。</p>

    <h2 id="publish">3. 先准备，再执行</h2>
    <p>一次发布分为两个阶段。先编写请求文档并准备发布，再读取返回的审批令牌：</p>
    <pre data-label="post.json"><code>{"{\n  \"type\": \"prepare\",\n  \"content\": { \"text\": \"Syndroo publishes from the command line.\" },\n  \"targets\": [{ \"provider\": \"bluesky\" }]\n}"}</code></pre>
    <pre data-label="terminal"><code>{"syndroo publish --input post.json --json"}</code></pre>
    <p>在终端中，命令会显示冻结后的预览，并询问{" "} <code>{"Publish to N accounts? [y/N/v]"}</code>：只有明确输入 <code>{"y"}</code> 才会发送；输入 <code>{"v"}</code> 会展开完整的冻结预览并再次询问；输入 <code>{"n"}</code>、空行或到达输入末尾都会取消，不发送任何内容。<code>{"--yes"}</code> 会自动确认本次刚刚准备的冻结意图，不再提示。使用 <code>{"--json"}</code> 且不使用 <code>{"--yes"}</code> 时，返回的唯一信封是准备结果，即带有 <code>{"approvalToken"}</code> 的 <code>{"confirmation_required"}</code>，命令以退出码 0 结束且不发送内容；使用 <code>{"--yes --json"}</code> 时，单次调用会准备、确认并执行，只输出一个最终信封，不会再输出准备结果或审批令牌。要执行一个已准备的结果，请从标准输入把令牌传回：</p>
    <pre data-label="execute.json"><code>{"{ \"type\": \"execute\", \"approvalToken\": \"<token>\" }"}</code></pre>
    <pre data-label="terminal"><code>{"syndroo publish --input - < execute.json --json"}</code></pre>
    <p>执行请求只会从标准输入读取，绝不会从文件路径或 <code>{"--data"}</code> 读取，因此有效令牌不会留在 shell 历史或进程参数中。</p>

    <h2 id="status">4. 读取结果</h2>
    <p><code>{"syndroo status"}</code> 可回答五种查询。传入发布结果中的操作 ID 可查看单个操作，也可分页查看最近的操作：</p>
    <pre data-label="terminal"><code>{"syndroo status --operation <operationId> --json\nsyndroo status --operations --limit 20 --json"}</code></pre>
    <p>一次投递的结果可能是 <code>{"succeeded"}</code>；带处置状态 <code>{"not_applied"}</code> 的 <code>{"failed"}</code>；<code>{"unknown"}</code>；或在从未进入调用时出现的 <code>{"not_started"}</code>。未知和未发送是不同事实：未知写入可能已被接受，因此它始终不可重试，应人工检查平台，而不是重新发送；从未开始的目标则明确没有发送。退出码保留同一区分，完整的值见{" "}<a href="/zh/reference/cli/#exit-codes">退出码表</a>。</p>
