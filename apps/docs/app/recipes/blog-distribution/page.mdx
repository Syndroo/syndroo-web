        <h1 id="blog-summary">Recipe: publish a blog summary</h1>
        <p className="lede">Turn a finished article into one short post per platform. The summarizing and the article reading happen in your client; Syndroo receives finished text and publishes it.</p>

        <div className="callout info">
          <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth="2" strokeLinecap="round" aria-hidden="true"><circle cx="12" cy="12" r="9" /><path d="M12 16v-5" /><path d="M12 8h.01" /></svg>
          <div>
            <span className="callout-title">Syndroo does not read your feed or write summaries.</span>
            <p>There is no RSS reader, no crawler, no model call and no content generation inside the Worker. Your script, agent or CMS prepares the text; the API publishes exactly what the request contains.</p>
          </div>
        </div>

        <h2 id="inputs">Inputs</h2>
        <ul>
          <li><strong>Article title and canonical URL.</strong> The URL is part of the text, not a separate field.</li>
          <li><strong>A summary you wrote or accepted.</strong> Keep it inside each platform's limit, and confirm it before sending.</li>
          <li><strong>A stable key.</strong> The article slug plus a revision works well: republishing an edited article is a different post, so give it a different key.</li>
          <li><strong>A Worker URL and API key</strong> in the environment your client reads: <code>{"SYNDROO_URL"}</code> and <code>{"SYNDROO_API_KEY"}</code>. The key can publish, so keep it out of prompts, logs, commits and issues.</li>
          <li><strong>A configured platform.</strong> The example below targets Bluesky only, so the run stays small; configure it with the <a href="/platforms/bluesky/">Bluesky guide</a> first.</li>
        </ul>

        <h2 id="steps">Steps</h2>
        <ol className="steps">
          <li>
            <h3 id="prepare-the-text">Prepare the text outside Syndroo</h3>
            <p>Read the article, write the summary, and paste both into the request. For Bluesky, HTTP(S) URLs receive link facets, so the link becomes a real link without extra work.</p>
          </li>
          <li>
            <h3 id="send">Send the request</h3>
            <div data-code-scope="publish">
              <pre data-label="POST /v1/posts"><code>{"curl -X POST \"$SYNDROO_URL/v1/posts\" \\\n  -H \"Authorization: Bearer $SYNDROO_API_KEY\" \\\n  -H \"Content-Type: application/json\" \\\n  -H \"Idempotency-Key: blog-safe-cross-posting-v1\" \\\n  --data '{\n    \"content\": \"New post: building retry-safe cross-posting with one idempotency key per logical post. https://syndroo.com/blog/safe-cross-posting-with-idempotency/\",\n    \"platforms\": [\"bluesky\"]\n  }'"}</code></pre>
            </div>
          </li>
          <li>
            <h3 id="expected-acceptance">Expected acceptance</h3>
            <pre data-label="202 Accepted"><code>{"{\n  \"id\": \"post_...\",\n  \"status\": \"queued\"\n}"}</code></pre>
          </li>
          <li>
            <h3 id="read-back">Read the result and keep the link</h3>
            <pre data-label="terminal"><code>{"curl \\\n  -H \"Authorization: Bearer $SYNDROO_API_KEY\" \\\n  \"$SYNDROO_URL/v1/posts/post_...\""}</code></pre>
            <pre data-label="GET /v1/posts/{id}"><code>{"{\n  \"id\": \"post_...\",\n  \"status\": \"published\",\n  \"publications\": [\n    {\n      \"platform\": \"bluesky\",\n      \"status\": \"published\",\n      \"attempts\": 1,\n      \"externalId\": \"at://...\",\n      \"externalUrl\": \"https://bsky.app/profile/.../post/...\",\n      \"errorAmbiguous\": false\n    }\n  ]\n}"}</code></pre>
            <p>Store the platform's <code>{"externalUrl"}</code> next to the article if you want to show where the post landed. The marketing demo shows an example link and labels it as one, because a simulated run has no real post behind it.</p>
          </li>
        </ol>

        <h2 id="failure-handling">Failure handling</h2>
        <div className="table-wrap">
          <table>
            <thead>
              <tr><th scope="col">What you see</th><th scope="col">What happened</th><th scope="col">What to do</th></tr>
            </thead>
            <tbody>
              <tr>
                <th scope="row"><code>{"INVALID_CONTENT"}</code></th>
                <td>The summary is longer than the platform allows.</td>
                <td>Shorten it and send a new request with a new key, or use an override for that platform.</td>
              </tr>
              <tr>
                <th scope="row"><code>{"errorAmbiguous: true"}</code></th>
                <td>The post may exist on the platform even though the call failed.</td>
                <td>Look at the account before publishing again. An automatic resend can create a duplicate.</td>
              </tr>
              <tr>
                <th scope="row">Repeating the same request</th>
                <td>Same key and same body were sent twice.</td>
                <td>Expect HTTP <code>{"200"}</code> with <code>{"replayed: true"}</code> and the original post: the identical request is answered from the stored result instead of being published again.</td>
              </tr>
              <tr>
                <th scope="row">Editing the summary, keeping the key</th>
                <td>The key is already bound to the original text.</td>
                <td>Expect HTTP <code>{"409"}</code> <code>{"IDEMPOTENCY_CONFLICT"}</code>. Use a new key for the edited summary.</td>
              </tr>
            </tbody>
          </table>
        </div>
