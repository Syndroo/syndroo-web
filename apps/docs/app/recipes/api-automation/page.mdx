        <h1 id="api-automation">Recipe: call Syndroo from CI or a script</h1>
        <p className="lede">A pipeline step publishes one post and then waits for the real per-platform outcome, instead of treating an accepted request as a finished job. The key is derived from the change, so a repeated run with the same key and the same body is answered from the stored result instead of publishing again.</p>

            <span className="callout-title">This publishes for real.</span>
            <p>The script below sends a real post to the platforms you configure. Run it against your own Worker first, and keep the API key in the pipeline's secret store: pass it through the environment, never on the command line, and never with shell tracing enabled.</p>

        <h2 id="inputs">Inputs</h2>
        <ul>
          <li><strong><code>{"SYNDROO_URL"}</code> and <code>{"SYNDROO_API_KEY"}</code></strong> as pipeline secrets. The key can publish, so it needs the same handling as a password.</li>
          <li><strong><code>{"GIT_COMMIT"}</code> or another reproducible identifier.</strong> It becomes the idempotency key, so the same logical post always produces the same key. The API accepts 1-128 characters from letters, digits, dot, underscore, colon and hyphen.</li>
          <li><strong>The text</strong>, already assembled by the pipeline and inside each platform's limit.</li>
          <li><strong>A decision for <code>{"partial"}</code></strong>: the script fails the job by default, and a person decides what happens next.</li>
          <li><strong>Node.js 22 or newer</strong> - the same floor as the Worker - and network access to your deployment. No packages to install: the script uses <code>{"fetch"}</code> and <code>{"JSON"}</code>.</li>
        </ul>

        <h2 id="steps">Steps</h2>
        <ol className="steps">
          <li>
            <h3 id="create-the-script">Create the script</h3>
            <p>Save this as <code>{"publish.mjs"}</code> next to your pipeline configuration.</p>
            <pre data-label="publish.mjs"><code>{"// Node.js 22 or newer, no dependencies.\n// Environment: SYNDROO_URL, SYNDROO_API_KEY, GIT_COMMIT (optional POLL_INTERVAL_MS).\nconst { SYNDROO_URL: base, SYNDROO_API_KEY: apiKey, GIT_COMMIT: commit } = process.env;\n\nconst KEY_PATTERN = /^[A-Za-z0-9._:-]{1,128}$/;\nconst REQUEST_TIMEOUT_MS = 15000;\nconst MAX_POLLS = 10;\n\nif (!base || !apiKey) {\n  console.error(\"SYNDROO_URL and SYNDROO_API_KEY must be set\");\n  process.exit(2);\n}\nif (!commit) {\n  console.error(\"GIT_COMMIT must be set\");\n  process.exit(2);\n}\n\n// Validate the value that is actually sent as the idempotency key.\nconst postKey = `deploy-${commit}`;\nif (!KEY_PATTERN.test(postKey)) {\n  console.error(\"the idempotency key must be 1-128 characters of letters, digits, dot, underscore, colon or hyphen\");\n  process.exit(2);\n}\n\nconst intervalMs = Number(process.env.POLL_INTERVAL_MS ?? 15000);\nif (!Number.isInteger(intervalMs) || intervalMs < 0 || intervalMs > 60000) {\n  console.error(\"POLL_INTERVAL_MS must be an integer between 0 and 60000\");\n  process.exit(2);\n}\n\nconst terminal = new Set([\"published\", \"partial\", \"failed\"]);\nconst waiting = new Set([\"queued\", \"scheduled\", \"publishing\"]);\n\n// Diagnostics stay bounded: a status and an error code, never a response body,\n// which can echo request content straight back into a CI log.\nfunction describe(status, json) {\n  const code = json?.error?.code;\n  const safe = typeof code === \"string\" && /^[A-Z][A-Z0-9_]{0,63}$/.test(code) ? code : \"no error code\";\n  return `HTTP ${status} (${safe})`;\n}\n\nasync function requestJson(url, init) {\n  let response;\n  try {\n    response = await fetch(url, { ...init, signal: AbortSignal.timeout(REQUEST_TIMEOUT_MS) });\n  } catch (error) {\n    console.error(`request ended without a response (${error?.name ?? \"network error\"}); nothing was resubmitted`);\n    process.exit(2);\n  }\n\n  let json = null;\n  try {\n    json = JSON.parse(await response.text());\n  } catch {\n    json = null;\n  }\n  return { response, json };\n}\n\n// Only the post's own status and each publication's own status are read here.\nfunction printResult(post) {\n  console.log(`post status: ${post.status}`);\n  for (const publication of post.publications ?? []) {\n    const code = publication.errorCode ?? \"-\";\n    const attempts = publication.attempts ?? \"?\";\n    console.log(`  ${publication.platform}  ${publication.status}  ${code}  attempts ${attempts}  ambiguous ${publication.errorAmbiguous ?? false}`);\n  }\n}\n\nconst accepted = await requestJson(`${base}/v1/posts`, {\n  method: \"POST\",\n  headers: {\n    Authorization: `Bearer ${apiKey}`,\n    \"Content-Type\": \"application/json\",\n    \"Idempotency-Key\": postKey,\n  },\n  body: JSON.stringify({\n    content: `Deploy ${commit} is live: queue retries now respect an explicit deadline.`,\n    platforms: [\"bluesky\"],\n  }),\n});\n\nif (!accepted.response.ok) {\n  console.error(`POST rejected: ${describe(accepted.response.status, accepted.json)}`);\n  process.exit(2);\n}\n\nconst postId = accepted.json?.id;\nif (typeof postId !== \"string\" || postId.length === 0) {\n  console.error(\"POST answered without a usable post id; not polling\");\n  process.exit(2);\n}\nconsole.log(`accepted post: ${postId}`);\n\nfor (let attempt = 1; attempt <= MAX_POLLS; attempt += 1) {\n  const poll = await requestJson(`${base}/v1/posts/${encodeURIComponent(postId)}`, {\n    headers: { Authorization: `Bearer ${apiKey}` },\n  });\n\n  if (!poll.response.ok) {\n    console.error(`GET failed: ${describe(poll.response.status, poll.json)}`);\n    process.exit(2);\n  }\n\n  const status = typeof poll.json?.status === \"string\" ? poll.json.status : null;\n  if (status === null) {\n    console.error(\"GET response carried no usable status; stopping instead of polling blindly\");\n    process.exit(2);\n  }\n  if (terminal.has(status)) {\n    printResult(poll.json);\n    process.exit(status === \"published\" ? 0 : 1);\n  }\n  if (!waiting.has(status)) {\n    console.error(\"GET response carried an unrecognised status; stopping without echoing it\");\n    process.exit(2);\n  }\n\n  await new Promise((resolve) => setTimeout(resolve, intervalMs));\n}\n\nconsole.error(`still waiting after ${MAX_POLLS} checks: ${base}/v1/posts/${postId}`);\nconsole.error(\"not resubmitting automatically; check the post before sending anything again\");\nprocess.exit(1);"}</code></pre>
          </li>
          <li>
            <h3 id="what-the-script-does">What the script guarantees</h3>
            <ul>
              <li><strong>The body is built as JSON, not as text.</strong> <code>{"JSON.stringify"}</code> escapes the commit id, so a quote or a backslash in the environment cannot break the request.</li>
              <li><strong>The final key and the poll interval are validated before anything is sent.</strong> An unusable key or interval exits with code 2 without contacting the Worker.</li>
              <li><strong>Every request has a deadline and log lines stay bounded.</strong> Requests time out after 15 seconds, and failures print an HTTP status and an error code rather than a response body, which could echo request content into the log.</li>
              <li><strong>Non-2xx answers stop the run.</strong> <code>{"401"}</code>, <code>{"409"}</code>, <code>{"503"}</code> and every other failure exit with code 2; a request that ends without a response also stops the run and says nothing was resubmitted.</li>
              <li><strong>No usable post id, no polling.</strong> A response without a non-empty <code>{"id"}</code> fails the job rather than polling a guessed URL.</li>
              <li><strong>Only the top-level status drives the loop.</strong> A publication that is already <code>{"published"}</code> or <code>{"failed"}</code> never stands in for the post's own status, and an unparsable or unrecognised status stops the run instead of polling blindly.</li>
              <li><strong>Per-platform results are printed.</strong> The job log says which platform failed, with its error code, attempt count and ambiguity flag.</li>
              <li><strong>Nothing is resubmitted.</strong> If the poll budget runs out, the script exits non-zero and says so.</li>
            </ul>
          </li>
          <li>
            <h3 id="run-it">Run it from the pipeline</h3>
            <pre data-label="pipeline step"><code>{"export SYNDROO_URL=\"https://your-worker.your-subdomain.workers.dev\"\nexport SYNDROO_API_KEY=\"$SYNDROO_API_KEY_SECRET\"\nexport GIT_COMMIT=\"$GIT_COMMIT\"\nnode publish.mjs"}</code></pre>
            <p>A repeated run of the same commit sends the same key and the same body, so the API answers with the original post and <code>{"replayed: true"}</code> instead of publishing a second time.</p>
          </li>
        </ol>

        <h2 id="failure-handling">Failure handling</h2>
        <div className="table-wrap">
          <table>
            <thead>
              <tr><th scope="col">Situation</th><th scope="col">Exit</th><th scope="col">Correct behaviour in a pipeline</th></tr>
            </thead>
            <tbody>
              <tr>
                <th scope="row">HTTP <code>{"202"}</code> with <code>{"status: queued"}</code></th>
                <td>continues</td>
                <td>Keep the id and poll. Acceptance is not delivery.</td>
              </tr>
              <tr>
                <th scope="row">HTTP <code>{"200"}</code> with <code>{"replayed: true"}</code></th>
                <td>continues</td>
                <td>The pipeline retried an identical request; the original post is reused.</td>
              </tr>
              <tr>
                <th scope="row">HTTP <code>{"401"}</code> <code>{"UNAUTHORIZED"}</code></th>
                <td>2</td>
                <td>Stop. Fix the secret. Never loop on authentication failures.</td>
              </tr>
              <tr>
                <th scope="row">HTTP <code>{"409"}</code> <code>{"IDEMPOTENCY_CONFLICT"}</code></th>
                <td>2</td>
                <td>The key already belongs to different text. Decide by hand whether this is the same post; use a new key only for genuinely new content.</td>
              </tr>
              <tr>
                <th scope="row">HTTP <code>{"503"}</code> <code>{"SERVICE_UNAVAILABLE"}</code></th>
                <td>2</td>
                <td>Maintenance mode is refusing new posts. Retry later with the same key and the same body; reads keep working.</td>
              </tr>
              <tr>
                <th scope="row">Post status <code>{"partial"}</code></th>
                <td>1</td>
                <td>Fail the job and report per platform. There is no retry endpoint: do not create a new request or a new key that targets the platforms which already published, because that would post again. Re-sending the identical key and body is safe and returns the stored result.</td>
              </tr>
              <tr>
                <th scope="row"><code>{"errorAmbiguous: true"}</code> on a publication</th>
                <td>1</td>
                <td>Never auto-retry. Mark the job as needing a person and check the platform by hand.</td>
              </tr>
              <tr>
                <th scope="row">Poll budget exhausted</th>
                <td>1</td>
                <td>Report the post URL and stop. Do not resubmit; a slow publication is still a publication.</td>
              </tr>
            </tbody>
          </table>
