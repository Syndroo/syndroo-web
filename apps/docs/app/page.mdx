    <p className="lede">The <code>{"syndroo"}</code> command publishes from this machine, in the foreground, with no Syndroo server in the path. It has exactly three first-level commands, plus global flags:{" "} <code>{"syndroo connect"}</code>, <code>{"syndroo publish"}</code> and{" "} <code>{"syndroo status"}</code>.{" "} <strong>0.7.0-rc.1 candidate; fixture-tested, unpublished, and live-account acceptance still pending.</strong></p>

    <div className="table-wrap">
      <table>
        <thead>
          <tr>
            <th scope="col">Command</th>
            <th scope="col">What it does</th>
          </tr>

          <tr>
            <th scope="row"><code>{"syndroo connect <provider>"}</code></th>
            <td>Start, resume or maintain one provider connection. Credentials come from an explicit source; Core stores them and the plugin never sees the connection record.</td>
          </tr>
          <tr>
            <th scope="row"><code>{"syndroo publish --input <file>"}</code></th>
            <td>Prepare, execute or retry a publication. Preparing freezes the content and returns an approval token; executing needs that token on standard input.</td>
          </tr>
          <tr>
            <th scope="row"><code>{"syndroo status"}</code></th>
            <td>Read providers, connections and operations. Read-only: it never contacts a platform and never repairs local state.</td>
          </tr>

    <h2 id="install">1. Build the candidate</h2>
    <p>Node.js 24.19 or newer on macOS or Linux. The candidate is not on a registry, so it is built from the product repository and packed from its workspace:</p>
    <pre data-label="terminal"><code>{"git clone https://github.com/Syndroo/syndroo\ncd syndroo\nnpm ci\nnpm run build\nnpm pack --workspace @syndroo/cli --pack-destination ./artifacts\nnpm install --global ./artifacts/syndroo-cli-0.7.0-rc.1.tgz"}</code></pre>
    <p><a href="/getting-started/local-cli/">Local CLI</a> covers the configuration file, the state root and the first run in full.</p>

    <h2 id="connect">2. Connect one account</h2>
    <p><code>{"syndroo connect"}</code> reads exactly one credential source: the environment variable <code>{"SYNDROO_CREDENTIALS"}</code> with <code>{"--from-env"}</code>, or a private JSON file with <code>{"--credential-file"}</code>. It never reads a{" "} <code>{".env"}</code> file and never guesses.</p>
    <pre data-label="terminal"><code>{"export SYNDROO_CREDENTIALS='{\"identifier\":\"you.bsky.social\",\"password\":\"APP_PASSWORD_PLACEHOLDER\"}'\nsyndroo connect bluesky --from-env --label work"}</code></pre>
    <p>The exact field names for all five providers are in{" "} <a href="/reference/credentials/">Credentials</a>, and each{" "} <a href="/platforms/">platform guide</a> shows where the credential comes from.</p>

    <h2 id="publish">3. Prepare, then execute</h2>
    <p>A publication is two phases. Write a request document, prepare it, and read the approval token that comes back:</p>
    <pre data-label="post.json"><code>{"{\n  \"type\": \"prepare\",\n  \"content\": { \"text\": \"Syndroo publishes from the command line.\" },\n  \"targets\": [{ \"provider\": \"bluesky\" }]\n}"}</code></pre>
    <pre data-label="terminal"><code>{"syndroo publish --input post.json --json"}</code></pre>
    <p>On a terminal the command prints the frozen preview and asks for a confirmation; in{" "} <code>{"--json"}</code> it returns <code>{"confirmation_required"}</code> with an{" "} <code>{"approvalToken"}</code> and exits 0 without sending anything. Execute by feeding that token back on standard input:</p>
    <pre data-label="execute.json"><code>{"{ \"type\": \"execute\", \"approvalToken\": \"<token>\" }"}</code></pre>
    <pre data-label="terminal"><code>{"syndroo publish --input - < execute.json --json"}</code></pre>
    <p>An execute request is only ever read from standard input, never from a file path or{" "} <code>{"--data"}</code>, so a token cannot be left in a shell history or in process arguments.</p>

    <h2 id="status">4. Read the result</h2>
    <p><code>{"syndroo status"}</code> answers five queries. Pass the operation id from the publish result to see one operation, or page through the recent ones:</p>
    <pre data-label="terminal"><code>{"syndroo status --operation <operationId> --json\nsyndroo status --operations --limit 20 --json"}</code></pre>
    <p>A delivery is <code>{"succeeded"}</code>, <code>{"failed"}</code> with disposition{" "} <code>{"not_applied"}</code>, or <code>{"unknown"}</code>. An unknown write stays non-retryable: inspect the platform by hand instead of resending. The exit code carries the same distinction, and <a href="/reference/cli/#exit-codes">the exit code table</a> lists it.</p>
