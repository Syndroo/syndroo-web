        <h1 id="quick-start">Quickstart</h1>
        <p className="lede">The <code>{"syndroo"}</code> command publishes from this machine, in the foreground, with no Syndroo server in the path. It supports five local providers: Bluesky, Threads, LinkedIn personal, Mastodon public text, and DEV.to articles. <strong>0.7.0-rc.1 candidate; fixture-tested, unpublished, and live-account testing pending.</strong></p>

        <div className="tip">

          <p>Start with a dry run when you want to inspect the parsed document. A preview sends nothing, resolves no credentials, and writes no local state.</p>
        </div>

        <h2 id="install">1. Install</h2>
        <p>Requires Node.js 22 or newer on macOS or Linux. Windows is not supported for local writes. The candidate is installed from the tarball this repository builds; it is not on npm.</p>
        <pre data-label="terminal"><code>{"git clone https://github.com/Syndroo/syndroo\ncd syndroo\nnpm ci\nnpm run build\nnpm run pack:cli\nnpm install --global ./artifacts/syndroo-cli-0.7.0-rc.1.tgz\nsyndroo init --namespace default\nsyndroo doctor --local"}</code></pre>

        <h2 id="bind-one-account">2. Connect one account</h2>
        <p><code>{"syndroo connect"}</code> defaults to local mode and reads exactly one credential source. An interactive run offers environment variables, an existing file, hidden terminal entry, and, for Mastodon only, browser authorization. This example uses a Bluesky app password:</p>
        <pre data-label="terminal"><code>{"export BLUESKY_IDENTIFIER=\"your-handle.bsky.social\"\nexport BLUESKY_PASSWORD=\"APP_PASSWORD_PLACEHOLDER\"\nsyndroo connect bluesky --from-env\nsyndroo auth status --local"}</code></pre>
        <p><a href="/accounts/">Account configuration</a> covers all five providers, exact environment variables and credential-file fields, safe credential saving, and Mastodon OAuth.</p>

        <h2 id="publish">3. Publish</h2>
        <p>Save a text document as <code>post.json</code>.</p>
        <pre data-label="post.json"><code>{"{\n  \"schemaVersion\": 1,\n  \"key\": \"first-post-001\",\n  \"content\": \"Syndroo now publishes from the command line.\",\n  \"platforms\": [\"bluesky\"]\n}"}</code></pre>
        <p>Publishing sends directly after confirmation. One command reads the input once, validates it, and sends that same parsed snapshot:</p>
        <pre data-label="terminal"><code>{"syndroo publish --input post.json --yes --no-input --json"}</code></pre>
        <p>Adding <code>{"--dry-run"}</code> previews the parsed document instead. A preview is read-only and requires existing local config and bindings:</p>
        <pre data-label="terminal"><code>{"syndroo publish --input post.json --dry-run --json"}</code></pre>
        <p>For one-off content, pass the document inline with <code>{"--data"}</code>. Only one input source is allowed per run, and <code>{"--data"}</code> is never a place for credentials.</p>
        <pre data-label="terminal"><code>{"syndroo publish --data '{\"key\":\"first-post-001\",\"content\":\"Syndroo now publishes from the command line.\",\"platforms\":[\"bluesky\"]}' --yes --no-input --json"}</code></pre>
        <p>When the content should stay out of the process arguments, read it from stdin with <code>{"--input -"}</code> instead. DEV.to articles use a separate <code>{"schemaVersion"}</code> <code>{"2"}</code> document; see <a href="/publishing/#devto-article">the DEV.to article example</a>.</p>

        <h2 id="read-the-result">4. Read the result</h2>
        <p>Each target reports its own status, attempts, remote id and url. For an <code>{"unknown"}</code> target, inspect the platform by hand and do not resend.</p>
        <pre data-label="terminal"><code>{"syndroo receipts show <result.operationId> --json"}</code></pre>
